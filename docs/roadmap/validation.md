# Validation and Acceptance Plan

## Authority and claim rule

This document is the sole normative owner of support claims and required evidence. It proves public requirements in [Product contract](product-contract.md) and invariants in [Architecture](architecture.md); it does not redefine either. [Delivery plan](delivery-plan.md) owns when a row gates implementation or release.

All `VAL-*` rows are fixed Phase 1 evidence requirements; their required observations are unchanged by delivery's split gate. A finite positive row may be `failed`, `inconclusive`, or `implementation-qualified`; a finite negative row may be `failed`, `inconclusive`, or `exclusion-proven`. None is a support state. Changing a row or candidate requires the owning contract edit, affected evidence rerun, and applicable review. A Linux/platform/filesystem tuple, public native Git identity, shell, mise declaration/backend/package class, chezmoi entry/template behavior, or parser behavior is **unsupported** until VAL-001 and its complete Phase 6 installed-binary vertical pass. Selected gitlinks, private transport/authentication, provider-backed rendering, and host-fact-dependent behavior are exclusions and can never become support through an MVP proof row.

Cloud conformance is local source validation, not a new `VAL-*` qualification row. Its current scope is disposable `./internal/proof/...` race checks, all-package vet/configured lint, read-only module verification, an unchanged-old-entrypoint compile, cloud-script boundary tests, the ARCH-030 replacement import gate, the local parser source/effective-selection pin and upstream parser race suite, and race checks for the introduced `internal/paths`, `internal/safefs`, `internal/profile`, `internal/receipt`, `internal/toolchain` and the private `internal/state` replacement-record foundation and `tools/importcheck`. A source-bound report must distinguish `passed`, `failed` and `not-exercised`; inventory-only mode and missing required local checks cannot pass the cloud gate. Kernel/distribution/filesystem/tool/CA inventory records observed differences without running host-qualification probes, and `host_qualified=false` and `release_supported=false` remain unconditional. Even matching inventory cannot qualify any candidate; missing real-host rows remain not exercised and the candidate dispositions above remain inconclusive. Future replacement implementation additionally requires focused permanent replacement tests/race checks and its phase-specific reviews. Mock/local refusal results never replace the mandatory cgroup, namespace, btrfs, exact-tool/CA or installed-binary matrix.

Permanent encoder checks must cover exact reviewed bytes/digest vectors, permutations, duplicate collisions, nil/empty equivalence, invalid UTF-8, string/count/path limits, reservation boundaries and overflow, success/failure caller preservation and retained-history behavior. False independent receipt dimensions alone do not grant or deny completion authority: ARCH-024/026 state/current validation owns the applicable observed success relation. Receipt phase facts sort lexically; journal completed phases retain their exact execution prefix.

The production schedule is one checked sum `F + A + C + S + J + sum(T) + U`, at most 8,000,000 bytes:

| Term | Exact charge / basis |
|---|---|
| `F` | 2,048 for a candidate or 4,096 for completed facts: retained top-level scalar/model values, fixed-schema scratch and digest tokens. The frozen x86_64 layouts are 480-byte `Candidate` and 848-byte `Completed`; these fixed allowances cover their value copies and all three possible 71-byte tree/result tokens. |
| `A` | Every caller collection's full capacity times its conservative element width. Recurse into all retained spare elements for accounting only, including hidden nested collections and string payloads. |
| `C` | Every internally copied collection's visible length times the same element width, recursing only into copied visible elements. Sorting is in-place on those private copies. |
| `S` | Logical byte lengths of every retained field string, including spare backing values. Immutable strings share their payload; copied string headers are already charged in `C`. Aliases may be conservatively charged more than once. |
| `J` | Exact final JSON byte length, including default escaping and framing, measured by the same allocation-free writer before allocation. The private output has exactly this capacity, cannot grow and is returned directly. |
| `sum(T)` | Exact JSON byte length of every component-tree hashing pass. These intermediate buffers are charged cumulatively even though they need not remain live together. |
| `U` | `2,048 + 16 * len(Source.URI)` for the bounded pinned-Go `net/url`/`netip` parsing, error/value and canonical-serialization scratch. The URI is at most 2,048 bytes; this is charged before parsing. |

Conservative collection element widths in bytes are string 16, lock 32, file 48, tool 56, executable/tool observation 64, component 72 and destination observation 96. Capacity and copy products, payloads and buffer sizes use checked arithmetic before any input-dependent allocation. Structural reservation and JSON sizing perform no input-dependent allocation; URI parsing, copies, sorting, tree buffers and final emission follow the complete successful reservation. Spare backing values are accounted for without being validated or encoded. The fixed schema is acyclic. This reviewed logical-capacity schedule is not a measurement of allocator metadata, hidden caller string-substring backing, stacks, GC or a hard runtime-memory cap under PC-042.

The 16,384-string limit belongs to candidates, not to all completed-receipt fields. Completed facts retain their owned per-collection bounds and the same whole-invocation reservation; 4,096 targets with matching preconditions/results may legitimately exceed 16,384 strings. The source value check follows PC-020 URI syntax without granting DNS, public-endpoint, acquisition or source-ID authority. Typed value tests are not positive evidence for actual source materialization.

Go 1.24's pooled `encoding/json.Marshal`/`Encoder.Encode` remain differential test oracles, never the replacement production emitter. The owner-approved private encoder introduces no process-wide pool, retained historical scratch or toolchain patch. Complete byte/digest vectors, Unicode/control/HTML escaping, decimal boundaries, omission rules and no-growth failures must remain differential-tested on the pinned toolchain. Existing disposable proof string-cost checks still are not complete production reservation evidence. Actual archive authentication, complete installed-tree verification and current/state authority remain separate mandatory service checks; synthetic fixture comparisons establish none of them.
